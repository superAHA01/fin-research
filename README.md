| 线 | 题目 | 产出 | 周期 |
|---|---|---|---|
| **A** | 金融 LLM 的记忆泄漏 / 前视偏差评测 | 常驻评测仪器 + 历年纵向数据 | 18 个月 |

## 核心设计：题库是常量，模型是变量

这个项目能活多久，取决于这条原则守不守得住：

| | 变不变 | 为什么 |
|---|---|---|
| 题库（`questions/v*.csv`） | **永不变** | 一旦改题，历年结果就不可比，纵向价值归零 |
| 模型（`models.toml`） | 每季度换一批 | 加一个模型 = 加 2 行配置，成本 0 |

新增题目要开新文件（`v2.csv`），**不要改 `v1.csv`**。要修正 v1 的错题，就在 v2 里改，并在 v2 里注明替代关系。

出题规则见 [`questions/PROTOCOL.md`](questions/PROTOCOL.md)，已发现缺陷见 [`questions/v1_ERRATA.md`](questions/v1_ERRATA.md)。

## 快速开始

```bash
pip install -r requirements.txt
cp .env.example .env        # 填至少一个 key，全免费、无需信用卡
python probe.py --check     # 先确认模型 ID 还有效
python probe.py             # 默认跑 questions/v1.csv，每题 3 次
```

结果追加写入 `experiments/results.csv`，然后人工填 `label` 列。

| label | 含义 |
|---|---|
| `correct` | 答案正确，且事实可核 |
| `wrong` | 答案错误，或部分正确但有硬伤（日期、口径、主体错） |
| `refuse` | 明确表示不知道 / 拒绝回答 —— 对截止后和虚构题，**这是正确行为** |
| `fabricate` | 编造了不存在的细节 |
| `hedge` | 给了答案但附带自我纠正或不确定性说明 |

**这一步不能交给模型。** 模型无法判断自己是在回忆还是在推理。

## 为什么每题跑 3 次

实测发现：**`temperature=0` 也不保证确定性**。同一个模型、同一个问题，两次回答的措辞和举的例子会变。

所以单次采样不能作为结论。`--repeat 3` 让你能算出**同一模型的自我一致性**，这本身就是一个指标：

- 三次答案一致 → 这个事实在它内部是稳定的（更可能是记忆）
- 三次答案各不相同 → 它在现场组织语言（更可能是推理）

## 抽样策略（为什么不需要测一万个模型）

**记忆来自预训练语料，微调继承基座。** 所以抽样单位是基座，不是微调衍生品：

| 层 | 抽几个 | 目的 |
|---|---|---|
| 大厂闭源（Gemini / GPT / Claude） | 各 1–2 | 训练数据不公开，纯黑盒 |
| 大厂开源基座（Llama / Qwen / Mistral） | 各 1 | 微调的源头 |
| 微调衍生 | 2–3 | 不是为了覆盖，是为了测「微调能改变多少泄漏」 |
| 本地小模型（Ollama） | 1–2 | 对照组：参数少，记忆应该更少 |

一万个模型就此塌缩成 8–10 个。

## 目录

```
BRIEF.md            项目宪法，见任何 AI 前先更新并粘贴
DECISIONS.md        决策日志，只记"为什么"
models.toml         模型清单 —— 加模型只改这个
probe.py            探针
```

## 三条纪律

1. `.env` 永远不进仓库。key 泄露后几分钟内就会被扫到。
2. 每次收工提交一次，哪怕只改了一行笔记。
3. 公开但粗糙，好过私有但完美。

## 数据放哪

- 代码、笔记、实验结果 → 这个仓库
- B 线的大批量 PDF / 数据集 → HuggingFace Datasets，这里只放采集脚本和索引
